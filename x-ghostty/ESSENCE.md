# ESSENCE — x-ghostty

## モチベーション

複数のプロジェクトを同時に抱えて進めるようになり、とりわけ AI エージェントを複数
並列で走らせるようになった結果、「1 作業 = 1 ウィンドウ / 1 タブ」という端末の粒度が
破綻した。タブは一覧性がなく、ウィンドウは重い。加えて作者は、全体像を把握しないと
気が済まない性質である。

この製品が目指す理想は、**全プロジェクトを一望する大局視点と、個々のプロジェクトの
端末作業に没入する局所視点とがシームレスに行き来でき、かつ大局視点から各プロジェクト
を統括管理できる TUI 型ワークスペース**である。統括管理に並ぶべき情報は、人間が
書き込むもの(ノート・優先度・締切)と、端末が自ら観測したもの(入力待ち・実行中・
正常終了・異常終了)の両方であり、後者も理想の一部である。

大局視点と局所視点の接続そのものは、既存の group レイヤー(group の列挙・
`toggle_group_zoom`・Cmd+1〜9 の序数ジャンプ)によって既に達成されている。統括管理の
最初の一歩であるプロジェクトごとのノート、および大局視点の情報密度を担う
プライマリーペインも実現済みである。

ノートを実際に使った結果、プロジェクトは一時的な画面分割ではなく「情報を預ける場所」に
なった。それに伴い見えた 3 つの欠落 — 預けた情報の保全、書き込みの自然さ、統括情報の
不足(優先度・締切) — は、前回の改訂で必須対応事項へ取り込み済みである。

運用を続けた結果、次の欠落が見えた。抱えるプロジェクトの数や構成は日々変わるのに、
大局視点の画面配置は hide/show と手動リサイズを繰り返して毎回作り直しており、その
手間が全体像の一望を妨げている。理想は、画面配置を登録レイアウトから一手で整えられる
ことである。また、作者は作業単位を頭の中で「プロジェクト」と呼んでいるのに、製品の
語彙は「グループ」のままであり、この不一致も解消する。今回は、hide の選択式化・
登録レイアウトの適用・「プロジェクト」への全面改名の 3 つを実装する。

利用者は基本的に作者一人である。将来的に他者が使う可能性は否定しないが、
今回の成功は「作者が使えること」で判定する。

## 思想

1. **全体像の把握が最優先。** この製品は「複数プロジェクトを抱える人間が、全体像を
   失わずに前進する」ために存在する。機能の追加可否に迷ったら「それは全体像の把握を
   助けるか」で判断する。

2. **端末領域を恒久的に食う UI は作らない。** 追加 UI は呼び出したときだけ現れ、
   抜ければ端末が全面に戻る。常時表示と迷ったら、常時表示しない側を選ぶ。

3. **上流由来のターミナルコアは極力触らない。** VT 実装・レンダラ・フォントスタック・
   シェル統合は Ghostty から継承した資産であり、fork 固有の機能は macOS アプリ層と
   action 層に閉じる。コアの改変なしに実現できない要求が出た場合は、勝手に踏み込まず
   人間に相談する。

4. **判断ロジックはモデル層に置く。** 「何を表示するか」「何を保存するか」の判断を
   View に持たせない。検証可能性は後付けの品質目標ではなく設計制約である。テストしやすい
   設計とそうでない設計で迷ったら、テストしやすい方を選ぶ。

5. **速度より正しさ。** 期限がないため、動くが根拠のない実装より、遅くても検証された
   実装を選ぶ。

必ず人間に委ねる判断:

- キーバインドの割り当て(既存キーとの衝突が判明した場合の代替キー選定を含む)
- UI の最終的な見た目
- 単一ウィンドウ・タブ無しという構造そのものを変える判断

## 前提事項

- 本プロジェクトは Ghostty(MIT License)の fork であり、macOS 専用・単一ウィンドウ
  である。GTK(Linux/FreeBSD)アプリ、タブ、複数ウィンドウ、quick terminal、
  AppleScript、App Intents、Services 連携は既に削除済みである。
- ビルドには Zig 0.15.x と Xcode を要する。主要コマンドは `zig build`
  (macOS アプリを含むフルビルド)、`just test`(Zig コアのテスト)、
  `just swift-test`(Swift のユニットテスト `XGhosttyTests`)である。
  `just build-app` は `zig build` と等価の薄いラッパーであり、自動検証では
  `zig build` を直接用いる。
- `XGhosttyUITests` は headless 環境でクラッシュするため、自動検証の対象にしない。
- プロジェクトレイヤー(旧 group レイヤー)は `macos/Sources/Features/Groups/` 配下に
  Swift で閉じており、改名に伴いディレクトリ・ファイル名も `Projects/` 系へ改名する。
  ノート・プライマリーペイン・優先度・締切・hide 選択・レイアウト適用もここに実装し、
  ノート・優先度・締切の状態は `GroupState`(改名後 `ProjectState`)に持たせる。
  keybind の追加は既存のプロジェクト action と同じ流儀に従う。
- fork 固有の機能のために新規の外部依存は追加しない。
- `SPEC.md`(プロジェクトレイヤーの設計書)、`AGENTS.md`、`README.md` は実装
  ドキュメントであり、実装に合わせて更新してよい。仕様書と実装を乖離させないことを
  優先する。
- Linux 対応は将来の可能性として存在するが、プロジェクトレイヤー自体が Swift に閉じて
  いる以上、それはレイヤーごとの再設計を伴う独立した大仕事である。したがって今回の
  実装は移植性を一切考慮せず、Swift に閉じて作る。
- 明確な期限はない。
- 本プロジェクトは GUI アプリケーションであり、画面の見た目は自動検証できない。
  目視確認は人間が実機で行う。
- xcodebuild / zig のツールチェーンは OS sandbox 下で構造的に動作しない
  (XPC サービス接続、ユーザー一時領域への書込み、依存取得のネットワーク)。
  自律セッションは OS sandbox を外して運用する。
- profile: unsandboxed

## 必須対応事項

1. プロジェクトごとに、人間が手書きする短いノートを保持できる。
2. ノートは最大 10 行とし、10 行を超えて保持しない。
3. ノートはプロジェクト名と同様に永続化され、アプリ再起動後に同じプロジェクトへ
   復元される。
4. ノートはプロジェクトに属し、プロジェクト内のペイン(split)には属さない。
5. `Cmd+N` で focused プロジェクトのノート編集オーバーレイが開き、複数行を編集でき、
   `Cmd+Enter` で保存して閉じる。
6. ノート編集オーバーレイで Esc を押すと、編集内容を破棄して閉じ、開く前の本文が
   保持される。破棄に確認は挟まない。
7. `Cmd+Enter` の既定割り当てである fullscreen を解除する。
8. `Cmd+Opt+N` で一望モードをトグルし、visible な全プロジェクトの上にそれぞれのノートが
   同時にオーバーレイ表示される。再度 `Cmd+Opt+N` を押すか Esc を押すと抜ける。
9. 一望モードの表示対象は visible なプロジェクトのみとし、hidden なプロジェクトの
   ノートは表示しない。
10. zoom 中に一望モードへ入った場合は zoom を解除してから全プロジェクトに重ねる。
11. 一望モードは閲覧専用とし、モード中にノート編集も focus 移動も行わない。
12. 一望モードで枠に収まらないノートは切り詰めて表示し、レイアウトを壊さない。
    編集オーバーレイでは全文が見える。
13. ノートに関する UI は端末領域を恒久的に占有しない。呼び出したときだけ表示され、
    抜ければ端末が全面に戻る。
14. 既存のプロジェクト機能(列挙・zoom・序数ジャンプ・hide/show・resize/equalize・
    rename・close)および上流由来のターミナル動作を退行させない。ただし以下の意図的
    変更は例外とする:`Cmd+Enter` の fullscreen 既定割り当ての解除(fullscreen は
    `Ctrl+Cmd+F`・Window メニュー・緑ボタンから引き続き到達できる)、全体ビューの
    描画をプライマリーペインのみに変えること、全体ビューでのペイン系操作の no-op 化、
    zoom 解除時に focus をプライマリーペインへ寄せること、プロジェクトを閉じる操作の
    確認を常時化すること、最後のペインのシェル exit でプロジェクトを閉じず終了済み
    状態で残すこと、ノート編集オーバーレイ中の Cmd+A / C / X / V をエディタのテキスト
    編集に向けること、`Cmd+S` / `Cmd+Shift+S` へのソートアクションの新規割り当て、
    `Cmd+Opt+H` の即時 hide を hide 選択画面に置き換えること、`Cmd+L` へのレイアウト
    選択の新規割り当て、「グループ」→「プロジェクト」への全面改名(文言・action 名・
    識別子・ディレクトリ名)。
15. ノートの保持・復元・表示対象の判断ロジックはモデル層に置き、`XGhosttyTests` から
    検証可能にする。
16. `SPEC.md` と `README.md` を、実装したノート層の仕様に合わせて更新する。
    `README.md` の Building 節には `zig build` / `just test` / `just swift-test` の
    3 つの検証コマンドをすべて載せる。
17. 各ペインはプライマリーフラグを持つ。プロジェクト内の最初のペインはプライマリーとし、
    それ以降に作られたペインは非プライマリーとする。
18. プライマリーペインはプロジェクト内で常に 1 つのみとする。
19. 全体ビュー(非 zoom)では、各プロジェクトはプライマリーペインのみを描画する。
    プロジェクトに zoom した局所視点では従来どおり全ペインをレイアウトのまま表示する。
20. 全体ビューでのキーボード入力・focus はプライマリーペインへ向く。zoom 解除時に
    focus がプライマリー以外のペインにあった場合はプライマリーへ寄せる。
21. 全体ビューではペイン系操作(分割・ペイン間 focus 移動・ペイン zoom・ペインの
    resize/equalize)を no-op とする。ペイン操作は zoom 中のみ有効とする。
22. zoom 中に focused ペインをプライマリーへ指定する action を追加し、`Cmd+P` に
    割り当てる(素の `Cmd+P` に既存割り当てが無いことは確認済み)。指定時、元の
    プライマリーは解除される。
23. プライマリーペインが閉じた場合(シェルの exit・`Cmd+W`・process 死のいずれでも)、
    プロジェクトに他のペインがあれば分割木上の最近傍 leaf を昇格する。プライマリーが
    最後のペインの場合は 28〜31 項に従う(シェル exit では終了済み状態で残り、
    close 操作では確認を経て閉じる)。
24. プライマリーフラグはペインレイアウトと同じ経路で永続化され、アプリ再起動後に
    同じペインへ復元される。不正な保存(プライマリー 0 個/複数)は復元時に 1 つへ
    正規化する。
25. プライマリーの印は、zoom 中かつプロジェクト内に複数ペインがあるときだけ、
    プライマリーペインの右上に表示する。全体ビューおよび単一ペインのプロジェクトでは
    表示しない。
26. プライマリーの判断ロジック(既定付与・唯一性・昇格・復元時正規化・全体ビューの
    表示対象)はモデル層に置き、`XGhosttyTests` から検証可能にする。
27. `SPEC.md` と `README.md` を、実装したプライマリーペイン層の仕様に合わせて更新する。
28. プロジェクトを閉じる操作(`close_group`、および最後のペインでの `Cmd+W`)では、
    実行中プロセスの有無によらず常に確認ダイアログを表示する。ダイアログは既存の
    実行中プロセス確認と同じ形式(Cancel / Close)を流用する。
29. 最後のペインのシェルが exit したとき(正常終了・異常終了・process 死のいずれでも)、
    プロジェクトを閉じず、ペインを「終了済み」状態のまま残す。ノートを含むプロジェクト
    の情報は保持される。
30. 終了済み状態のペインで Enter を押すと、新しいシェルが起動して同じペインで作業を
    再開できる。
31. プロジェクトとその情報(ノート等)が失われる経路は、確認ダイアログを経た明示的な
    close 操作のみとする。アプリ終了・再起動では従来どおり全プロジェクトが復元される。
32. ノート編集オーバーレイ表示中は、標準的なテキスト編集ショートカット(Cmd+A 全選択・
    Cmd+C コピー・Cmd+X 切り取り・Cmd+V 貼り付け)がエディタに対して効く。
33. 貼り付けにより 10 行を超えた場合も、従来の手入力と同様、保存時に先頭 10 行へ
    切り詰める(2 項の挙動を変えない)。
34. プロジェクトごとに優先度(high / medium / low / 未設定)を設定できる。既定は
    未設定。
35. プロジェクトごとに締切(日付のみ、時刻なし)を設定できる。既定は未設定。不正な
    日付入力は保存時に弾き、未設定として扱う。
36. 優先度・締切は `Cmd+N` のノート編集オーバーレイ内で設定・変更でき、ノートと同様に
    永続化され、アプリ再起動後に同じプロジェクトへ復元される。
37. プロジェクトのラベル帯に、優先度の控えめな印と締切を表示する。未設定の項目は
    表示しない。
38. 一望モードでは、ノートと併せて優先度・締切を表示する。
39. 締切を過ぎたプロジェクトは、ラベル帯・一望モードで控えめに強調する。強調は
    「超過」の 1 段階のみとし、「間近」等の段階分けはしない。
40. visible なプロジェクトを優先度順(high → medium → low → 未設定。同順位内は現在の
    相対順を維持)に実レイアウトごと並び替えるアクションを追加し、`Cmd+S` に
    割り当てる(素の `Cmd+S` に既存割り当てが無いことは確認済み)。
41. visible なプロジェクトを締切順(近い順。未設定は末尾、同日内は現在の相対順を維持)
    に実レイアウトごと並び替えるアクションを追加し、`Cmd+Shift+S` に割り当てる
    (`Cmd+Shift+S` に既存割り当てが無いことは確認済み)。
42. ソートは明示的なアクション実行時のみ行い、優先度・締切の変更によって自動では
    並び替えない。ソート後の並びは次のソート実行まで維持され、序数ジャンプ
    (Cmd+1〜9)はソート後の並びに追従する。
43. ソートの対象は visible なプロジェクトのみとし、hidden なプロジェクトは影響を
    受けない。
44. 優先度・締切の保持・復元・ソート順・締切超過判定・終了済み状態の判断ロジックは
    モデル層に置き、`XGhosttyTests` から検証可能にする。
45. `SPEC.md` と `README.md` を、実装した削除保護・ショートカット対応・優先度・締切層の
    仕様に合わせて更新する。
46. `Cmd+Opt+H` は「focused プロジェクトを即座に隠す」挙動を廃止し、hide 選択画面を
    開く。選択画面には visible な全プロジェクトが列挙され、複数をトグル選択でき、
    Enter で選択したプロジェクトを一括で hidden にし、Esc で何も隠さず閉じる
    (zoom 中に呼び出した場合の挙動は定めず、実装に任せる)。
47. hide 選択では visible な全プロジェクトを隠すことはできず、最低 1 つは visible に
    残る。
48. 隠したプロジェクトの復帰導線は従来どおり hidden シェルフとし、変更しない。
49. 組み込みの登録レイアウトとして、等分割(プロジェクト数 4〜9 の 6 種)と X+1
    (X = 4〜8 の 5 種。X 個を等分割し、1 個を最下段に全幅横長で配置)の計 11 種を
    持つ。
50. 等分割は、行数を √n に最も近い整数とするグリッドに、プロジェクトを上の行から
    できるだけ均等に配る(4 = 2+2、5 = 3+2、6 = 3+3、7 = 3+2+2、8 = 3+3+2、
    9 = 3+3+3)。行の高さは等分、行内の各プロジェクトの幅は等分とする。X+1 の X 部分
    も同じ規則で配置する。
51. `Cmd+L` でレイアウト選択オーバーレイが開き、登録レイアウトの一覧から矢印キーで
    選択して Enter で適用し、Esc で何も変えずに閉じる。オーバーレイは呼び出したとき
    だけ表示され、抜ければ端末が全面に戻る(zoom 中に呼び出した場合の挙動は定めず、
    実装に任せる)。
52. レイアウト適用時、visible なプロジェクトは現在の序数順のまま、スロットへ
    「上の行から、行内は左から右、+1 枠は最後」の順で割り当てる。序数(Cmd+1〜9)は
    適用後の配置に追従する。
53. レイアウトのプロジェクト数が現表示数より多い場合、不足分の新規プロジェクトを
    序数の末尾に作成してから適用する。新規プロジェクトは通常の新規作成と同様に
    新しいシェルを起動する。
54. レイアウトのプロジェクト数が現表示数より少ない場合、隠すプロジェクトを選ぶ
    選択画面を表示し、超過分(現表示数 − レイアウト数)ちょうどを選択したときのみ
    確定できる。確定で選択したプロジェクトが hidden になり(close はされず情報は
    失われない)、残りのプロジェクトで適用する。Esc でレイアウト適用ごとキャンセル
    する。
55. レイアウト適用はその時点の配置変更であり、「適用中のレイアウト」という状態は
    持たない。適用後の手動 resize・分割・ソートは従来どおり可能で、配置は従来どおり
    保存・復元される。
56. hide 選択・レイアウトのスロット計算・数合わせ(新規作成数・隠す数)・割り当て順の
    判断ロジックはモデル層に置き、`XGhosttyTests` から検証可能にする。
57. 「グループ」を「プロジェクト」へ全面改名する:ユーザー可視文言(メニュー・
    ダイアログ・シェルフ等)、fork 固有の action 名(`hide_group` → `hide_project`
    等)、コード内部識別子(`GroupState` → `ProjectState` 等)、ディレクトリ・
    ファイル名(`macos/Sources/Features/Groups/` → `Projects/` 等)、および
    SPEC.md / README.md の用語。上流由来のターミナルコアの語彙・識別子には触れない。
58. 改名は挙動を変えない純粋なリネームとし、既存機能を退行させない。キーバインド設定
    等の後方互換は従来どおり保証しない。
59. `SPEC.md` と `README.md` を、実装した hide 選択・レイアウト適用の仕様と改名後の
    語彙に合わせて更新する。

## 任意対応事項

- ヘッダー帯のクリック等、マウスからノートを開く導線(今回はキーバインドのみで足りる。
  余力があれば)。
- ノート編集オーバーレイ・一望モード・プライマリー印の見た目の洗練(配色・余白・
  アニメーション)。
- 全体ビューで、プロジェクトに非プライマリーペインがあるとき、その存在が分かる控えめな
  インジケータ(例:ペイン数バッジ)の表示。

## 非対応事項

恒久的にやらないこと:

- タブ、複数ウィンドウ、quick terminal、AppleScript、App Intents、Services 連携の復活。
- 上流 Ghostty への追従、および上流へのコントリビュート。
- 他者向けの整備:署名済み配布物(.app / Homebrew)、ユーザー向けドキュメント、
  設定の後方互換保証。
- ノートの外部同期(クラウド保存、ファイル書き出し、他デバイス共有)。
- ユーザー定義レイアウトの登録機能(登録レイアウトは組み込み 11 種で完結する)。
- `SPEC.md` の「2. 非目的」に列挙済みの各項目:tmux / zellij 互換、floating pane、
  live session 完全復元、scrollback / PTY 状態の永続復元、drag & drop による
  プロジェクト移動、プロジェクト入れ替え UI。

現段階では実施しないこと(将来の昇格候補):

- 端末が観測した各プロジェクトのライブ状態表示(入力待ち・実行中・正常終了・異常終了)
  (現段階では実施しない。エージェントが入力待ちで止まっているのを見落とし、
  プロジェクトを長時間放置してしまう事象が実際に起きたら、update-essence で
  必須対応事項/任意対応事項への昇格を検討)。
- Linux / GTK 対応(現段階では実施しない。作者の常用開発マシンが macOS でなくなったら、
  update-essence で必須対応事項/任意対応事項への昇格を検討)。

## 遂行順序

順序へのこだわりは無く、Mercator の裁量に任せる。

## 用語

- **プロジェクト** — ユーザーから見た作業文脈の単位。旧称「グループ」であり、今回の
  改名で製品の語彙を「プロジェクト」に統一する。内部実装では `ProjectState` /
  `ProjectRef`(改名前 `GroupState` / `GroupRef`)が対応する。
- **大局視点** — zoom を解除し、visible な全プロジェクトが同時に画面に並んでいる状態。
- **局所視点** — 特定のプロジェクトに zoom し、その端末作業に没入している状態。
- **ノート** — プロジェクトに紐づく、人間が手書きする短いメモ。最大 10 行。
  プロジェクト名と同様に永続化される。
- **一望モード** — `Cmd+Opt+N` で入る閲覧専用モード。visible な全プロジェクトの上に
  それぞれのノートが同時にオーバーレイ表示される。zoom 中に入ると zoom は解除される。
- **全体ビュー** — 大局視点と同義。zoom していない状態で、visible な全プロジェクトが
  同時に画面に並んでいる画面。
- **プライマリーペイン** — プロジェクト内で常に 1 つだけ存在する代表ペイン。既定では
  最初に作られたペインがプライマリーとなる。全体ビューではこのペインだけが描画される。
  zoom 中に `Cmd+P` で focused ペインへ付け替えられる。
- **優先度** — プロジェクトに設定する high / medium / low / 未設定 の 4 値。既定は
  未設定。
- **締切** — プロジェクトに設定する日付(時刻なし)。未設定を許す。
- **ソート** — `Cmd+S`(優先度順)/ `Cmd+Shift+S`(締切順)で実行する明示的な
  並び替えアクション。visible なプロジェクトの実レイアウトと序数を並び替える。
- **終了済み状態** — 最後のペインのシェルが exit した後、プロジェクトが閉じずに
  残っている状態。ノート等の情報は保持され、Enter で新しいシェルを起動して再開できる。
- **hide 選択画面** — `Cmd+Opt+H` で開く選択画面。visible なプロジェクトから隠すもの
  を複数トグル選択し、Enter で一括 hide、Esc でキャンセルする。
- **hidden シェルフ** — 非 zoom 時の画面右上に hidden なプロジェクトを列挙する既存の
  復帰導線。
- **登録レイアウト** — 組み込み固定 11 種の画面配置テンプレート。等分割(4〜9)と
  X+1(X = 4〜8)からなる。
- **等分割** — 行数を √n に最も近い整数とするグリッドに、プロジェクトを上の行から
  できるだけ均等に配り、行高・行内幅を等分する配置。
- **X+1 レイアウト** — X 個を等分割の規則で上部に配置し、1 個を最下段に全幅横長で
  配置するレイアウト。
