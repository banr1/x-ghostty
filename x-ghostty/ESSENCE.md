# ESSENCE — x-ghostty

## モチベーション

複数のプロジェクトを同時に抱えて進めるようになり、とりわけ AI エージェントを複数
並列で走らせるようになった結果、「1 作業 = 1 ウィンドウ / 1 タブ」という端末の粒度が
破綻した。タブは一覧性がなく、ウィンドウは重い。加えて作者は、全体像を把握しないと
気が済まない性質である。

この製品が目指す理想は、**全プロジェクトを一望する大局視点と、個々のプロジェクトの
端末作業に没入する局所視点とがシームレスに行き来でき、かつ大局視点から各プロジェクト
を統括管理できる TUI 型ワークスペース**である。統括管理に並ぶべき情報は、人間が
書き込むもの(ノート・優先度・締切)と、端末が自ら観測したもの(入力待ち・実行中・
正常終了・異常終了)の両方であり、後者も理想の一部である。

大局視点と局所視点の接続そのものは、既存の group レイヤー(group の列挙・
`toggle_group_zoom`・Cmd+1〜9 の序数ジャンプ)によって既に達成されている。統括管理の
最初の一歩であるプロジェクトごとのノート、および大局視点の情報密度を担う
プライマリーペインも実現済みである。

ノートを実際に使った結果、プロジェクトは一時的な画面分割ではなく「情報を預ける場所」に
なった。それに伴い見えた 3 つの欠落 — 預けた情報の保全、書き込みの自然さ、統括情報の
不足(優先度・締切) — は、前回の改訂で必須対応事項へ取り込み済みである。

運用を続けた結果、次の欠落が見えた。抱えるプロジェクトの数や構成は日々変わるのに、
大局視点の画面配置は hide/show と手動リサイズを繰り返して毎回作り直しており、その
手間が全体像の一望を妨げていた。また、作者は作業単位を頭の中で「プロジェクト」と
呼んでいるのに、製品の語彙は「グループ」のままだった。この 2 点 — hide の選択式化・
登録レイアウトの適用・「プロジェクト」への全面改名 — は前回の改訂で必須対応事項へ
取り込み済みである。

続く改訂では、日々触る中で見えた 4 つの摩擦 — リモート split がローカルに戻ること、
hidden なプロジェクトを一望する場所がないこと、ノート編集の取り消し・やり直し、優先度の
毎朝リセット — を必須対応事項へ取り込み、実装済みである。

運用を続けた結果、当初の想定に反して、抱えるプロジェクトの数はさらに増えた。増えたのは
画面に同時に並べる数ではなく、抱えてはいるが今は画面に出していないプロジェクトの方で
ある。これに伴い、大局視点の主役が入れ替わる。これまでの大局視点は「画面に並ぶ端末
そのもの」であり、プロジェクト一覧は hidden の復帰導線に過ぎなかった。今回はこの主従を
逆転させ、**hidden を含む全プロジェクトを載せた一覧を、全体像を把握し統括管理する台帳に
昇格させ、画面配置はその一覧の状態から自動的に導かれる投影とする**。人間が画面配置に
持つ裁量は「同じ表示数に対する好みの割り方」だけになる。

台帳への昇格後、締切の入力だけが日付文字列のタイプを要し、台帳を素早く整える動作として
重いままだった。前回までの改訂で締切セルの Space 送りを必須対応事項へ取り込み済みである。

台帳へ日本語を書き込む日常の中で、プロジェクト一覧のセル編集(タイトル列・ノート列)
だけが日本語 IME 入力を受け付けない破れが顕在化した。ノート編集オーバーレイやタイトルの
ダブルクリック編集では効くのに、一覧のセルでは最初の 1 打鍵が素通しで確定され、以降の
未確定文字列を変換・確定しても反映されない。セル編集が標準的なテキスト入力として
振る舞うことはこれまで暗黙の当然の仕様であり、前回の改訂でこれを明文化して修正済み
である。

台帳を日々使い込む中で、次の摩擦群が見えた。一覧の操作系が台帳専用の独自方言
(Enter で下移動・Space で循環・使い捨てのソートアクション)のままで、テーブル UX
として完成されている Notion の流儀と食い違うこと。ソートが状態でないため、台帳が
「常に整った並び」を保てないこと。レイアウトの余りが前半の行に寄り、ソートで上位に
来る重要なプロジェクトの枠がかえって狭いこと。ノート 10 行の上限が実運用に足りず、
超過分が黙って切り捨てられること。増えたショートカットを一覧できる場所がないこと。
今回はこれらを、独自方言の発明ではなく優れた既存 UX(Notion)の踏襲という方針で
必須対応事項へ取り込む。

利用者は基本的に作者一人である。将来的に他者が使う可能性は否定しないが、
今回の成功は「作者が使えること」で判定する。

## 思想

1. **全体像の把握が最優先。** この製品は「複数プロジェクトを抱える人間が、全体像を
   失わずに前進する」ために存在する。機能の追加可否に迷ったら「それは全体像の把握を
   助けるか」で判断する。

2. **端末領域を恒久的に食う UI は作らない。** 追加 UI は呼び出したときだけ現れ、
   抜ければ端末が全面に戻る。常時表示と迷ったら、常時表示しない側を選ぶ。

3. **上流由来のターミナルコアは極力触らない。** VT 実装・レンダラ・フォントスタック・
   シェル統合は Ghostty から継承した資産であり、fork 固有の機能は macOS アプリ層と
   action 層に閉じる。コアの改変なしに実現できない要求が出た場合は、勝手に踏み込まず
   人間に相談する。

4. **判断ロジックはモデル層に置く。** 「何を表示するか」「何を保存するか」の判断を
   View に持たせない。検証可能性は後付けの品質目標ではなく設計制約である。テストしやすい
   設計とそうでない設計で迷ったら、テストしやすい方を選ぶ。

5. **速度より正しさ。** 期限がないため、動くが根拠のない実装より、遅くても検証された
   実装を選ぶ。

必ず人間に委ねる判断:

- キーバインドの割り当て(既存キーとの衝突が判明した場合の代替キー選定を含む)
- UI の最終的な見た目
- 単一ウィンドウ・タブ無しという構造そのものを変える判断

## 前提事項

- 本プロジェクトは Ghostty(MIT License)の fork であり、macOS 専用・単一ウィンドウ
  である。GTK(Linux/FreeBSD)アプリ、タブ、複数ウィンドウ、quick terminal、
  AppleScript、App Intents、Services 連携は既に削除済みである。
- ビルドには Zig 0.15.x と Xcode を要する。主要コマンドは `zig build`
  (macOS アプリを含むフルビルド)、`just test`(Zig コアのテスト)、
  `just swift-test`(Swift のユニットテスト `XGhosttyTests`)である。
  `just build-app` は `zig build` と等価の薄いラッパーであり、自動検証では
  `zig build` を直接用いる。
- `XGhosttyUITests` は headless 環境でクラッシュするため、自動検証の対象にしない。
- プロジェクトレイヤー(旧 group レイヤー)は `macos/Sources/Features/Projects/` 配下に
  Swift で閉じている(旧 `Groups/` からの改名は完了済み)。ノート・プライマリーペイン・
  優先度・締切・レイアウト適用・プロジェクト一覧・リモート split・優先度の毎朝リセット・
  一覧のセル編集と並べ替え・次トリガー・レイアウト型の記憶と自動適用・ソート状態・
  ショートカット一覧もここに実装し、ノート・優先度・締切・次トリガー・行順(手動順)・
  列順・ソート状態・レイアウト型の状態は `ProjectState` に持たせる。keybind の追加は
  既存のプロジェクト action と同じ流儀に従う。
- リモート split の前提として、リモート側のシェルでも Ghostty のシェル統合が動作し、
  OSC 7 でホスト名とカレントパスが報告される。新ペインの再接続は報告されたホスト名への
  `ssh <host>` とし、ユーザー名・鍵・ポートは `~/.ssh/config` 等の ssh 設定に任せる
  (元ペインの ssh コマンドラインは再現しない)。
- fork 固有の機能のために新規の外部依存は追加しない。
- `SPEC.md`(プロジェクトレイヤーの設計書)、`AGENTS.md`、`README.md` は実装
  ドキュメントであり、実装に合わせて更新してよい。仕様書と実装を乖離させないことを
  優先する。
- Linux 対応は将来の可能性として存在するが、プロジェクトレイヤー自体が Swift に閉じて
  いる以上、それはレイヤーごとの再設計を伴う独立した大仕事である。したがって今回の
  実装は移植性を一切考慮せず、Swift に閉じて作る。
- 明確な期限はない。
- 本プロジェクトは GUI アプリケーションであり、画面の見た目は自動検証できない。
  目視確認は人間が実機で行う。
- xcodebuild / zig のツールチェーンは OS sandbox 下で構造的に動作しない
  (XPC サービス接続、ユーザー一時領域への書込み、依存取得のネットワーク)。
  自律セッションは OS sandbox を外して運用する。
- profile: unsandboxed

      できるだけ均等に、割り切れない余りは後半の行に付くように配り — 前半の行ほど

      集合と一致する(例: n=9 は横長型と縦長型が形は同じでも向きが違うため畳まれない。

    - 行送りは上の行から左→右、列送りは左の列から上→下に、一覧の表示順の visible な
      行が割り当てられ、序数がそれに追従する
    - 型の選択が永続化され、復元される。保存が無いときは横長型・行送りになる
    - visible 数が変わる操作(表示トグル・`Cmd+Opt+H`・新規作成・close)の後、
      記憶している型で新しい数の配置が導かれる。変わらない操作では配置が変わらない

## 必須対応事項

1. プロジェクトごとに、人間が手書きする短いノートを保持できる。
2. ノートは最大 100 行とする。保存操作の時点で 100 行を超えている場合は確認を表示し、

   従来どおり黙って保存する。編集中の入力・貼り付け自体は制限しない。
3. ノートはプロジェクト名と同様に永続化され、アプリ再起動後に同じプロジェクトへ
   復元される。
4. ノートはプロジェクトに属し、プロジェクト内のペイン(split)には属さない。
5. `Cmd+E` で focused プロジェクトのノート編集オーバーレイが開き、複数行を編集でき、

   保持される。破棄に確認は挟まない。

8. `Cmd+Opt+E` で一望モードをトグルし、visible な全プロジェクトの上にそれぞれのノートが
   同時にオーバーレイ表示される。再度 `Cmd+Opt+E` を押すか Esc を押すと抜ける。
9. 一望モードの表示対象は visible なプロジェクトのみとし、hidden なプロジェクトの
   ノートは表示しない。
10. zoom 中に一望モードへ入った場合は zoom を解除してから全プロジェクトに重ねる。
11. 一望モードは閲覧専用とし、モード中にノート編集も focus 移動も行わない。
12. 一望モードで枠に収まらないノートは切り詰めて表示し、レイアウトを壊さない。

13. ノートに関する UI は端末領域を恒久的に占有しない。呼び出したときだけ表示され、

    日付入力は保存時に弾き、未設定として扱う。
36. 優先度・締切はプロジェクト一覧のセルで設定・変更でき(ノート編集オーバーレイからは
    設定しない)、ノートと同様に永続化され、アプリ再起動後に同じプロジェクトへ復元
    される。
37. プロジェクトのラベル帯に、優先度の控えめな印と締切を表示する。未設定の項目は
    表示しない。
38. 一望モードでは、ノートと併せて優先度・締切・次トリガーを表示する。
39. 締切を過ぎたプロジェクトは、ラベル帯・一望モードで控えめに強調する。強調は
    「超過」の 1 段階のみとし、「間近」等の段階分けはしない。
40. ソートは一覧の並びを規定する状態とする。状態は「手動 / next / show / deadline /
    priority」の 5 値で、既定は手動とする。ソート状態は永続化され、アプリ再起動後も
    維持される。ソートは状態なので、一覧を開いていない間も並び(序数を含む)を規定し
    続ける。
41. 各ソートキーの向きは固定とする。next は自分 → 外部 → イベント → 未設定、show は
    表示 → 非表示、deadline は日付の近い(古い)順で未設定は末尾、priority は
    high → medium → low → 未設定。いずれも安定ソート(同順位内は直前の表示順を維持)
    とし、対象は hidden を含む全行とする。序数(Cmd+1〜9)は表示順の visible な行を
    上から数えた順とする。
42. 一覧の表の最上部にソートバーを置き、5 値から選択できる。キーボードでは、セル
    カーソルが最上行にあるとき `↑` でソートバーへ乗り、`←→` で選び、`Enter` で適用して
    表へ戻る。`Esc` は適用せず表へ戻る。マウスのクリックでも選べる。ソートバーで手動を
    直接選んだ場合は、現在の表示順を手動順として引き継ぐ。
43. ソート有効中(手動以外)は、セル値の変更・新規作成・読み込み・優先度の毎朝リセット
    で即座に再ソートする。ソート有効中に `Opt+↑` / `Opt+↓` で行を動かそうとしたときは
    確認を表示し、OK なら現在の表示順を手動順として引き継いでソート状態を手動へ戻した
    上で入替を実行し、Cancel なら何もしない。手動状態では確認なしで入れ替わる。
    使い捨てのソートアクション(`Cmd+S` / `Cmd+Shift+S` への割り当て)は廃止する。
44. 優先度・締切・次トリガーの保持・復元・ソート順・締切超過判定・終了済み状態の判断
    ロジックはモデル層に置き、`XGhosttyTests` から検証可能にする。
45. `SPEC.md` と `README.md` を、実装した削除保護・ショートカット対応・優先度・締切層の
    仕様に合わせて更新する。
46. `Cmd+Opt+H` は focused プロジェクトを即座に hidden にする(選択画面は開かない)。
47. `Cmd+Opt+H`・一覧の表示トグルのいずれでも、visible な全プロジェクトを隠すことは
    できず、最低 1 つは visible に残る。
48. 隠したプロジェクトの復帰導線はプロジェクト一覧のみとし、hidden シェルフは廃止済みの
    ままとする。
49. レイアウト型は形(横長型・縦長型・台座型)と向き(行送り・列送り)の組み合わせと
    する。横長型は行数を √n に最も近い整数とするグリッドに、プロジェクトをできるだけ
    均等に、割り切れない余りは後半の行に付くように配る(前半の行ほど枠数が少なく、
    1 枠が広い。例: n=8 は上から 2+3+3)。行の高さと行内の幅は等分する。縦長型はその
    転置とする(左の列ほど枠数が少ない)。台座型は n−1 個を上部に配置し、1 個を最下段に
    全幅横長で置く。横長型・縦長型では向きは序数の進み方だけを変え、形は変えない。
    台座型では、行送りは上部を横長型の規則で、列送りは縦長型の規則で配置する。
50. 各 visible 数(1〜9)に対して、形 3 種 × 向き 2 種のうち配置も序数の進み方も
    完全に一致するものは 1 つに畳み、残りを選択肢とする。選択肢が 1 つのとき
    `Cmd+Opt+L` は選ぶものが無い旨を示すだけとする。
51. `Cmd+Opt+L` でレイアウト型の選択オーバーレイが開き、現在の visible 数に対する
    選択肢を矢印キーで選んで Enter で適用し、Esc で何も変えずに閉じる。プロジェクト数は
    一切変えない。オーバーレイは呼び出したときだけ表示され、抜ければ端末が全面に戻る
    (zoom 中に呼び出した場合の挙動は定めず、実装に任せる)。
52. 選んだレイアウト型は永続化され、アプリ再起動後も維持される。既定は横長型・行送りと
    する。
53. レイアウト適用時、visible なプロジェクトは一覧の表示順のまま、選んだ型の向きに
    従ってスロットへ割り当てる(行送りは上の行から左→右、列送りは左の列から上→下、
    台座型の最下段は最後)。序数(Cmd+1〜9)は適用後の配置に追従する。
54. visible なプロジェクトの数が変わったとき(一覧の表示トグル・`Cmd+Opt+H`・新規
    作成・close のいずれでも)、記憶しているレイアウト型で新しい数に対する配置を
    自動適用する。一覧を開いたまま切り替えた場合も背後で即座に組み直す。visible 数が
    変わらない操作(終了済み状態への遷移等)では発火しない。
55. プロジェクト単位のレイアウト resize / equalize を廃止する。zoom 中のプロジェクト内
    ペイン(split)の resize / equalize は従来どおり有効とする。
56. レイアウト型のスロット計算・完全一致の畳み込み・向きの割り当て順・自動適用の判断
    ロジックはモデル層に置き、`XGhosttyTests` から検証可能にする。

59. `SPEC.md` と `README.md` を、実装したレイアウト型・自動適用・hide の仕様と改名後の
    語彙に合わせて更新する。
60. リモートホストにいるペイン(シェル統合が OSC 7 で報告するホストがローカルでない)

63. `Cmd+L` でプロジェクト一覧オーバーレイをトグルする。表示中に再度 `Cmd+L` で閉じ、
    `Esc` では閉じない。zoom 中に開いた場合は zoom を解除せず zoom 画面の上に重ね、
    閉じると元の zoom 状態に戻る(`Cmd+N` 経由で開いた場合も同様)。一覧は hidden を

    オーバーレイはウィンドウの幅・高さそれぞれ 8 割程度を占め、呼び出したときだけ

64. 一覧の行の並びは visible / hidden で区画分けせず単一の並びとし、手動順・列順・

65. 一覧はセルカーソルを持ち、矢印キーで上下左右、`Tab` / `Shift+Tab` で右・左

    編集を取り消してセルカーソルへ戻る。
    表示列では `Enter` は表示のトグルとし、即時に hide/show を反映する(visible 最低

  update-essence で必須対応事項/任意対応事項への昇格を検討)。

## 遂行順序

順序へのこだわりは無く、Atlas Builder の裁量に任せる。

## 用語

- **プロジェクト** — ユーザーから見た作業文脈の単位。旧称「グループ」であり、製品の
  語彙は「プロジェクト」に統一済み。内部実装では `ProjectState` / `ProjectRef` が
  対応する。
- **大局視点** — zoom を解除し、visible な全プロジェクトが同時に画面に並んでいる状態。
- **局所視点** — 特定のプロジェクトに zoom し、その端末作業に没入している状態。
- **ノート** — プロジェクトに紐づく、人間が手書きする短いメモ。最大 100 行。
  プロジェクト名と同様に永続化される。
- **一望モード** — `Cmd+Opt+E` で入る閲覧専用モード。visible な全プロジェクトの上に
  それぞれのノート・優先度・締切・次トリガーが同時にオーバーレイ表示される。zoom 中に
  入ると zoom は解除される。
- **全体ビュー** — 大局視点と同義。zoom していない状態で、visible な全プロジェクトが
  同時に画面に並んでいる画面。
- **プライマリーペイン** — プロジェクト内で常に 1 つだけ存在する代表ペイン。既定では
  最初に作られたペインがプライマリーとなる。全体ビューではこのペインだけが描画される。
  zoom 中に `Cmd+P` で focused ペインへ付け替えられる。
- **優先度** — プロジェクトに設定する high / medium / low / 未設定 の 4 値。既定は
  未設定。「今日のフォーカス」を表し、毎朝ローカル 6:00 を境界に未設定へ戻る。
- **締切** — プロジェクトに設定する日付(時刻なし)。未設定を許す。
- **次トリガー** — プロジェクトを次に動かす主体。自分 / 外部 / イベント / 未設定の
  4 値。既定は未設定。旧「チームメンバー」は「外部」へ統合され、保存済みの値は
  読み込み時に移行される。人間が書き込む情報であり、端末が観測するライブ状態とは別物。
- **外部** — 次トリガーの一値。自分以外の人(チームメンバー・組織外の人を含む)。
- **ソート状態** — 一覧の並びを規定する状態。手動 / next / show / deadline / priority
  の 5 値で、各キーの向きは固定、安定ソート(同順位内は直前の表示順を維持)。
  ソートバーで選び、永続化される。有効中は値の変更で即時に再ソートされ、序数は
  表示順の visible な行を上から数えた順になる。
- **ソートバー** — 一覧の表の最上部にある、ソート状態の選択 UI。最上行から `↑` で乗り、
  `←→` と `Enter` で選ぶ。マウスでも選べる。
- **手動順** — ソート状態が手動のときの行順。ソート解除時は解除直前の表示順を
  引き継ぐ。
- **行選択** — セルカーソルで `Esc` を押して入る、行全体を選択した状態。`Delete` で
  確認を経たプロジェクト削除、`Enter` でセルカーソルへ復帰、`Esc` で解除。
- **日付候補** — 締切セルで `Enter` を押すと列挙される 10 択(今日〜7 日後・翌月同日・
  3 ヶ月後同日。実在しない同日は月末へ丸める)。`Aug 19` のような実日付で表示される。
- **ショートカット一覧** — `Cmd+/` でトグルする閲覧専用オーバーレイ。上流由来を含む
  有効なショートカットを場面ごとにグループ化して列挙する。
- **終了済み状態** — 最後のペインのシェルが exit した後、プロジェクトが閉じずに
  残っている状態。ノート等の情報は保持され、Enter で新しいシェルを起動して再開できる。
- **プロジェクト一覧** — `Cmd+L` でトグルする表形式のオーバーレイ。hidden を含む
  全プロジェクトを表示・タイトル・優先度・締切・次トリガー・ノートの列で列挙する台帳。
  Notion 流儀のセル操作(Enter 編集・Delete 削除・行選択)で編集でき、ソートバーを
  持ち、行順(手動順)・列順を `Opt+矢印` で入れ替えられる。新規プロジェクトの作成と
  hidden なプロジェクトの復帰の唯一の導線。表示順は序数(Cmd+1〜9)の元になる。
- **レイアウト型** — 表示数 n に対する画面配置の選択肢。形(横長型・縦長型・台座型)と
  向き(行送り・列送り)の組み合わせで定まり、完全一致するものは 1 つに畳む。
  `Cmd+Opt+L` で選び、選んだ型は記憶され、表示数が変わるたびに同じ型で自動適用される。
- **横長型** — 行数を √n に最も近い整数とするグリッドに、できるだけ均等に、余りは
  後半の行に付くように配り(前半の行ほど枠数が少なく 1 枠が広い)、行高・行内幅を
  等分する形。
- **縦長型** — 横長型の転置。列数を √n に最も近い整数とし、できるだけ均等に、余りは
  後半の列に付くように配り(左の列ほど枠数が少ない)、列幅・列内高を等分する形。
- **台座型** — n−1 個を上部に配置し、1 個を最下段に全幅で置く形。上部は、行送りでは
  横長型の規則、列送りでは縦長型の規則で配置する。
- **行送り / 列送り** — 序数(Cmd+1〜9)の進む向き。行送りは上の行から左→右、列送りは
  左の列から上→下。横長型・縦長型では向きは序数の進み方だけを変え、形は変えない。
- **リモートペイン** — シェル統合が OSC 7 で報告するホストがローカルでないペイン。
- **作業日** — ローカル時刻 6:00 から翌 6:00 までの区間。優先度リセットの単位。
