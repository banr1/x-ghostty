# ESSENCE — x-ghostty

## モチベーション

複数のプロジェクトを同時に抱えて進めるようになり、とりわけ AI エージェントを複数
並列で走らせるようになった結果、「1 作業 = 1 ウィンドウ / 1 タブ」という端末の粒度が
破綻した。タブは一覧性がなく、ウィンドウは重い。加えて作者は、全体像を把握しないと
気が済まない性質である。

この製品が目指す理想は、**全プロジェクトを一望する大局視点と、個々のプロジェクトの
端末作業に没入する局所視点とがシームレスに行き来でき、かつ大局視点から各プロジェクト
を統括管理できる TUI 型ワークスペース**である。統括管理に並ぶべき情報は、人間が
書き込むもの(ノート・優先度・締切)と、端末が自ら観測したもの(入力待ち・実行中・
正常終了・異常終了)の両方であり、後者も理想の一部である。

大局視点と局所視点の接続そのものは、既存の group レイヤー(group の列挙・
`toggle_group_zoom`・Cmd+1〜9 の序数ジャンプ)によって既に達成されている。統括管理の
最初の一歩であるプロジェクトごとのノート、および大局視点の情報密度を担う
プライマリーペインも実現済みである。

ノートを実際に使った結果、グループは一時的な画面分割ではなく「情報を預ける場所」に
なった。それに伴い、次の 3 つの欠落が見えた。第一に、預けた情報の保全 — 現状は
シェルの終了やグループの close でノートごと消えうる。第二に、書き込みの自然さ —
ノート編集中に標準的なテキスト編集ショートカットが効かない。第三に、統括情報の
不足 — 実際に使ってなお「どのプロジェクトから手を付けるか」をノートだけでは
決められない場面が発生した(延期していた優先度・締切の昇格トリガーの観測)。
今回はこの 3 つを埋める。

利用者は基本的に作者一人である。将来的に他者が使う可能性は否定しないが、
今回の成功は「作者が使えること」で判定する。

## 思想

1. **全体像の把握が最優先。** この製品は「複数プロジェクトを抱える人間が、全体像を
   失わずに前進する」ために存在する。機能の追加可否に迷ったら「それは全体像の把握を
   助けるか」で判断する。

2. **端末領域を恒久的に食う UI は作らない。** 追加 UI は呼び出したときだけ現れ、
   抜ければ端末が全面に戻る。常時表示と迷ったら、常時表示しない側を選ぶ。

3. **上流由来のターミナルコアは極力触らない。** VT 実装・レンダラ・フォントスタック・
   シェル統合は Ghostty から継承した資産であり、fork 固有の機能は macOS アプリ層と
   action 層に閉じる。コアの改変なしに実現できない要求が出た場合は、勝手に踏み込まず
   人間に相談する。

4. **判断ロジックはモデル層に置く。** 「何を表示するか」「何を保存するか」の判断を
   View に持たせない。検証可能性は後付けの品質目標ではなく設計制約である。テストしやすい
   設計とそうでない設計で迷ったら、テストしやすい方を選ぶ。

5. **速度より正しさ。** 期限がないため、動くが根拠のない実装より、遅くても検証された
   実装を選ぶ。

必ず人間に委ねる判断:

- キーバインドの割り当て(既存キーとの衝突が判明した場合の代替キー選定を含む)
- UI の最終的な見た目
- 単一ウィンドウ・タブ無しという構造そのものを変える判断

## 前提事項

- 本プロジェクトは Ghostty(MIT License)の fork であり、macOS 専用・単一ウィンドウ
  である。GTK(Linux/FreeBSD)アプリ、タブ、複数ウィンドウ、quick terminal、
  AppleScript、App Intents、Services 連携は既に削除済みである。
- ビルドには Zig 0.15.x と Xcode を要する。主要コマンドは `zig build`
  (macOS アプリを含むフルビルド)、`just test`(Zig コアのテスト)、
  `just swift-test`(Swift のユニットテスト `XGhosttyTests`)である。
  `just build-app` は `zig build` と等価の薄いラッパーであり、自動検証では
  `zig build` を直接用いる。
- `XGhosttyUITests` は headless 環境でクラッシュするため、自動検証の対象にしない。
- group レイヤーは `macos/Sources/Features/Groups/` 配下に Swift で閉じている。
  ノート・プライマリーペイン・優先度・締切もここに実装し、ノート・優先度・締切の
  状態は `GroupState` に持たせる。keybind の追加は既存の group action と同じ流儀に
  従う。
- fork 固有の機能のために新規の外部依存は追加しない。
- `SPEC.md`(group レイヤーの設計書)、`AGENTS.md`、`README.md` は実装ドキュメントで
  あり、実装に合わせて更新してよい。仕様書と実装を乖離させないことを優先する。
- Linux 対応は将来の可能性として存在するが、group レイヤー自体が Swift に閉じている
  以上、それは group レイヤーごとの再設計を伴う独立した大仕事である。したがって今回の
  実装は移植性を一切考慮せず、Swift に閉じて作る。
- 明確な期限はない。
- 本プロジェクトは GUI アプリケーションであり、画面の見た目は自動検証できない。
  目視確認は人間が実機で行う。
- xcodebuild / zig のツールチェーンは OS sandbox 下で構造的に動作しない
  (XPC サービス接続、ユーザー一時領域への書込み、依存取得のネットワーク)。
  自律セッションは OS sandbox を外して運用する。
- profile: unsandboxed

## 成功条件

1. `zig build` が exit 0 で終わる。
2. `just test` が exit 0 で終わる。
3. `just swift-test` が exit 0 で終わる。
4. `XGhosttyTests` に以下を検証するテストが存在し、成功する。
   - ノートを持つプロジェクトを保存し復元すると、同じノート本文が復元される
   - ノートは 10 行を超えて保持されない
   - ノート編集を保存して閉じると、編集後の本文が保持される
   - ノート編集を破棄して閉じると、開く前の本文が保持される
   - 一望モードの表示対象集合が visible なプロジェクトのみと一致し、hidden な
     プロジェクトを含まない
   - zoom 中に一望モードへ入ると zoom が解除される
   - 一望モード中に focus 移動もノート編集も発生しない
5. すべての実装が揃った後、人間が実機で一度だけ以下を目視確認し、確認が取れる。
   確認が取れるまで完了とはしない。
   - `Cmd+N` で focused プロジェクトのノート編集オーバーレイが開き、入力後
     `Cmd+Enter` で閉じると内容が保存されている
   - 入力後 Esc で閉じると入力が破棄され、開く前の本文が残っている
   - `Cmd+Enter` で fullscreen にならない
   - `Cmd+Opt+N` で visible な全プロジェクトの上にノートが同時表示され、
     再度 `Cmd+Opt+N` または Esc で消える
   - オーバーレイの見た目(位置・余白・配色)がターミナルに馴染んでいる
   - 一望モード時のノートが読める(切り詰め表示を含む)
6. `XGhosttyTests` に以下を検証するテストが存在し、成功する。
   - 新規グループの初期ペインがプライマリーになっている
   - 後続分割で作られたペインはプライマリーでなく、グループ内のプライマリーは
     常に 1 つである
   - 保存し復元すると同じペインにプライマリーが復元され、不正な保存(0 個/複数)は
     復元時に 1 つへ正規化される
   - プライマリーが閉じたとき、残ペインがあれば分割木上の最近傍 leaf が昇格する
   - 全体ビュー(非 zoom)の描画対象が各グループのプライマリーのみと一致する
   - 全体ビューではペイン系操作(分割・ペイン間 focus 移動・ペイン zoom・
     resize/equalize)が no-op になる
   - zoom 解除時に focus がプライマリーへ寄る
   - zoom 中の set_primary で focused ペインがプライマリーになり、元のプライマリーは
     解除される
7. プライマリーペインの実装が揃った後、人間が実機で一度だけ以下を目視確認し、
   確認が取れる。確認が取れるまで完了とはしない。
   - 全体ビューで各グループにプライマリーペインだけが表示される
   - zoom すると全ペインがレイアウトのまま表示され、複数ペインのときプライマリーの
     右上に印が見える
   - zoom 中 `Cmd+P` で focused ペインがプライマリーになり、zoom を抜けると
     全体ビューにそのペインが表示される
   - プライマリーのシェルを exit すると、残ペインの最近傍が昇格して全体ビューの
     表示が入れ替わる
   - 印の見た目がターミナルに馴染む
8. `XGhosttyTests` に以下を検証するテストが存在し、成功する。
   - グループを閉じる操作の確認要求が、実行中プロセスの有無によらず常に発生する
   - 最後のペインのシェルが exit してもグループは閉じず、終了済み状態になり、
     ノートが保持される
   - 複数ペインのグループで 1 ペインのシェルが exit したときは、そのペインだけが
     従来どおり閉じる
   - 終了済み状態のグループを保存し復元しても、ノートが保持されている
9. 削除保護の実装が揃った後、人間が実機で一度だけ以下を目視確認し、確認が取れる。
   確認が取れるまで完了とはしない。
   - アイドルなシェルだけのグループを close しようとすると確認ダイアログが出て、
     Cancel で何も失われない
   - 最後のペインのシェルを exit すると、グループが閉じずに終了済み表示で残る
   - 終了済みペインで Enter を押すと新しいシェルが起動し、作業を再開できる
   - 終了済み表示の見た目がターミナルに馴染む
10. ノート編集オーバーレイの実機確認として、Cmd+A / Cmd+C / Cmd+X / Cmd+V が
    エディタに対して標準どおり効き、10 行を超える貼り付けが保存時に先頭 10 行へ
    切り詰められることを人間が一度だけ目視確認し、確認が取れる。
11. `XGhosttyTests` に以下を検証するテストが存在し、成功する。
    - 優先度・締切を保存し復元すると同じ値が復元される
    - 不正な締切入力は未設定として扱われる
    - 優先度ソートが visible なグループを high → medium → low → 未設定の順に並べ、
      同順位内は元の相対順を維持する
    - 締切ソートが visible なグループを締切の近い順に並べ、未設定を末尾に置き、
      同日内は元の相対順を維持する
    - ソートが hidden なグループに影響しない
    - 締切超過の判定がモデル層で行われる
12. 優先度・締切の実装が揃った後、人間が実機で一度だけ以下を目視確認し、確認が
    取れる。確認が取れるまで完了とはしない。
    - `Cmd+N` のオーバーレイで優先度と締切を設定でき、保存後ラベル帯に表示される
    - 一望モードでノートと併せて優先度・締切が表示される
    - 締切超過のプロジェクトが控えめに強調されて見える
    - `Cmd+S` で優先度順、`Cmd+Shift+S` で締切順に並びが変わり、Cmd+1〜9 が
      新しい並びに追従する
    - 表示の見た目(印・締切・強調)がターミナルに馴染む

## 必須対応事項

1. プロジェクトごとに、人間が手書きする短いノートを保持できる。
2. ノートは最大 10 行とし、10 行を超えて保持しない。
3. ノートは group 名と同様に永続化され、アプリ再起動後に同じプロジェクトへ復元される。
4. ノートはプロジェクトに属し、プロジェクト内のペイン(split)には属さない。
5. `Cmd+N` で focused プロジェクトのノート編集オーバーレイが開き、複数行を編集でき、
   `Cmd+Enter` で保存して閉じる。
6. ノート編集オーバーレイで Esc を押すと、編集内容を破棄して閉じ、開く前の本文が
   保持される。破棄に確認は挟まない。
7. `Cmd+Enter` の既定割り当てである fullscreen を解除する。
8. `Cmd+Opt+N` で一望モードをトグルし、visible な全プロジェクトの上にそれぞれのノートが
   同時にオーバーレイ表示される。再度 `Cmd+Opt+N` を押すか Esc を押すと抜ける。
9. 一望モードの表示対象は visible なプロジェクトのみとし、hidden なプロジェクトの
   ノートは表示しない。
10. zoom 中に一望モードへ入った場合は zoom を解除してから全プロジェクトに重ねる。
11. 一望モードは閲覧専用とし、モード中にノート編集も focus 移動も行わない。
12. 一望モードで枠に収まらないノートは切り詰めて表示し、レイアウトを壊さない。
    編集オーバーレイでは全文が見える。
13. ノートに関する UI は端末領域を恒久的に占有しない。呼び出したときだけ表示され、
    抜ければ端末が全面に戻る。
14. 既存の group 機能(列挙・zoom・序数ジャンプ・hide/show・resize/equalize・rename・
    close)および上流由来のターミナル動作を退行させない。ただし以下の意図的変更は
    例外とする:`Cmd+Enter` の fullscreen 既定割り当ての解除(fullscreen は
    `Ctrl+Cmd+F`・Window メニュー・緑ボタンから引き続き到達できる)、全体ビューの
    描画をプライマリーペインのみに変えること、全体ビューでのペイン系操作の no-op 化、
    zoom 解除時に focus をプライマリーペインへ寄せること、グループを閉じる操作の
    確認を常時化すること、最後のペインのシェル exit でグループを閉じず終了済み状態で
    残すこと、ノート編集オーバーレイ中の Cmd+A / C / X / V をエディタのテキスト編集に
    向けること、`Cmd+S` / `Cmd+Shift+S` へのソートアクションの新規割り当て。
15. ノートの保持・復元・表示対象の判断ロジックはモデル層に置き、`XGhosttyTests` から
    検証可能にする。
16. `SPEC.md` と `README.md` を、実装したノート層の仕様に合わせて更新する。
    `README.md` の Building 節には `zig build` / `just test` / `just swift-test` の
    3 つの検証コマンドをすべて載せる。
17. 各ペインはプライマリーフラグを持つ。グループ内の最初のペインはプライマリーとし、
    それ以降に作られたペインは非プライマリーとする。
18. プライマリーペインはグループ内で常に 1 つのみとする。
19. 全体ビュー(非 zoom)では、各グループはプライマリーペインのみを描画する。
    グループに zoom した局所視点では従来どおり全ペインをレイアウトのまま表示する。
20. 全体ビューでのキーボード入力・focus はプライマリーペインへ向く。zoom 解除時に
    focus がプライマリー以外のペインにあった場合はプライマリーへ寄せる。
21. 全体ビューではペイン系操作(分割・ペイン間 focus 移動・ペイン zoom・ペインの
    resize/equalize)を no-op とする。ペイン操作は zoom 中のみ有効とする。
22. zoom 中に focused ペインをプライマリーへ指定する action を追加し、`Cmd+P` に
    割り当てる(素の `Cmd+P` に既存割り当てが無いことは確認済み)。指定時、元の
    プライマリーは解除される。
23. プライマリーペインが閉じた場合(シェルの exit・`Cmd+W`・process 死のいずれでも)、
    グループに他のペインがあれば分割木上の最近傍 leaf を昇格する。プライマリーが
    最後のペインの場合は 28〜31 項に従う(シェル exit では終了済み状態で残り、
    close 操作では確認を経て閉じる)。
24. プライマリーフラグはペインレイアウトと同じ経路で永続化され、アプリ再起動後に
    同じペインへ復元される。不正な保存(プライマリー 0 個/複数)は復元時に 1 つへ
    正規化する。
25. プライマリーの印は、zoom 中かつグループ内に複数ペインがあるときだけ、プライマリー
    ペインの右上に表示する。全体ビューおよび単一ペインのグループでは表示しない。
26. プライマリーの判断ロジック(既定付与・唯一性・昇格・復元時正規化・全体ビューの
    表示対象)はモデル層に置き、`XGhosttyTests` から検証可能にする。
27. `SPEC.md` と `README.md` を、実装したプライマリーペイン層の仕様に合わせて更新する。
28. グループを閉じる操作(`close_group`、および最後のペインでの `Cmd+W`)では、
    実行中プロセスの有無によらず常に確認ダイアログを表示する。ダイアログは既存の
    実行中プロセス確認と同じ形式(Cancel / Close Group)を流用する。
29. 最後のペインのシェルが exit したとき(正常終了・異常終了・process 死のいずれでも)、
    グループを閉じず、ペインを「終了済み」状態のまま残す。ノートを含むグループの
    情報は保持される。
30. 終了済み状態のペインで Enter を押すと、新しいシェルが起動して同じペインで作業を
    再開できる。
31. グループとその情報(ノート等)が失われる経路は、確認ダイアログを経た明示的な
    close 操作のみとする。アプリ終了・再起動では従来どおり全グループが復元される。
32. ノート編集オーバーレイ表示中は、標準的なテキスト編集ショートカット(Cmd+A 全選択・
    Cmd+C コピー・Cmd+X 切り取り・Cmd+V 貼り付け)がエディタに対して効く。
33. 貼り付けにより 10 行を超えた場合も、従来の手入力と同様、保存時に先頭 10 行へ
    切り詰める(2 項の挙動を変えない)。
34. プロジェクトごとに優先度(high / medium / low / 未設定)を設定できる。既定は
    未設定。
35. プロジェクトごとに締切(日付のみ、時刻なし)を設定できる。既定は未設定。不正な
    日付入力は保存時に弾き、未設定として扱う。
36. 優先度・締切は `Cmd+N` のノート編集オーバーレイ内で設定・変更でき、ノートと同様に
    永続化され、アプリ再起動後に同じプロジェクトへ復元される。
37. グループのラベル帯に、優先度の控えめな印と締切を表示する。未設定の項目は
    表示しない。
38. 一望モードでは、ノートと併せて優先度・締切を表示する。
39. 締切を過ぎたプロジェクトは、ラベル帯・一望モードで控えめに強調する。強調は
    「超過」の 1 段階のみとし、「間近」等の段階分けはしない。
40. visible なグループを優先度順(high → medium → low → 未設定。同順位内は現在の
    相対順を維持)に実レイアウトごと並び替えるアクションを追加し、`Cmd+S` に
    割り当てる(素の `Cmd+S` に既存割り当てが無いことは確認済み)。
41. visible なグループを締切順(近い順。未設定は末尾、同日内は現在の相対順を維持)に
    実レイアウトごと並び替えるアクションを追加し、`Cmd+Shift+S` に割り当てる
    (`Cmd+Shift+S` に既存割り当てが無いことは確認済み)。
42. ソートは明示的なアクション実行時のみ行い、優先度・締切の変更によって自動では
    並び替えない。ソート後の並びは次のソート実行まで維持され、序数ジャンプ
    (Cmd+1〜9)はソート後の並びに追従する。
43. ソートの対象は visible なグループのみとし、hidden なグループは影響を受けない。
44. 優先度・締切の保持・復元・ソート順・締切超過判定・終了済み状態の判断ロジックは
    モデル層に置き、`XGhosttyTests` から検証可能にする。
45. `SPEC.md` と `README.md` を、実装した削除保護・ショートカット対応・優先度・締切層の
    仕様に合わせて更新する。

## 用語

- **プロジェクト** — 本 fork の group と同義。ユーザーから見た作業文脈の単位であり、
  内部実装では `GroupState` / `GroupRef` が対応する。
- **大局視点** — zoom を解除し、visible な全プロジェクトが同時に画面に並んでいる状態。
- **局所視点** — 特定のプロジェクトに zoom し、その端末作業に没入している状態。
- **ノート** — プロジェクトに紐づく、人間が手書きする短いメモ。最大 10 行。
  group 名と同様に永続化される。
- **一望モード** — `Cmd+Opt+N` で入る閲覧専用モード。visible な全プロジェクトの上に
  それぞれのノートが同時にオーバーレイ表示される。zoom 中に入ると zoom は解除される。
- **全体ビュー** — 大局視点と同義。zoom していない状態で、visible な全プロジェクトが
  同時に画面に並んでいる画面。
- **プライマリーペイン** — グループ内で常に 1 つだけ存在する代表ペイン。既定では
  最初に作られたペインがプライマリーとなる。全体ビューではこのペインだけが描画される。
  zoom 中に `Cmd+P` で focused ペインへ付け替えられる。
- **優先度** — プロジェクトに設定する high / medium / low / 未設定 の 4 値。既定は
  未設定。
- **締切** — プロジェクトに設定する日付(時刻なし)。未設定を許す。
- **ソート** — `Cmd+S`(優先度順)/ `Cmd+Shift+S`(締切順)で実行する明示的な
  並び替えアクション。visible なグループの実レイアウトと序数を並び替える。
- **終了済み状態** — 最後のペインのシェルが exit した後、グループが閉じずに残っている
  状態。ノート等の情報は保持され、Enter で新しいシェルを起動して再開できる。
