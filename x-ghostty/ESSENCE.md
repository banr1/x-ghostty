# ESSENCE — x-ghostty

## モチベーション

複数のプロジェクトを同時に抱えて進めるようになり、とりわけ AI エージェントを複数
並列で走らせるようになった結果、「1 作業 = 1 ウィンドウ / 1 タブ」という端末の粒度が
破綻した。タブは一覧性がなく、ウィンドウは重い。加えて作者は、全体像を把握しないと
気が済まない性質である。

この製品が目指す理想は、**全プロジェクトを一望する大局視点と、個々のプロジェクトの
端末作業に没入する局所視点とがシームレスに行き来でき、かつ大局視点から各プロジェクト
を統括管理できる TUI 型ワークスペース**である。統括管理に並ぶべき情報は、人間が
書き込むもの(ノート・優先度・締切)と、端末が自ら観測したもの(入力待ち・実行中・
正常終了・異常終了)の両方であり、後者も理想の一部である。

大局視点と局所視点の接続そのものは、既存の group レイヤー(group の列挙・
`toggle_group_zoom`・Cmd+1〜9 の序数ジャンプ)によって既に達成されている。統括管理の
最初の一歩であるプロジェクトごとのノート、および大局視点の情報密度を担う
プライマリーペインも実現済みである。

ノートを実際に使った結果、プロジェクトは一時的な画面分割ではなく「情報を預ける場所」に
なった。それに伴い見えた 3 つの欠落 — 預けた情報の保全、書き込みの自然さ、統括情報の
不足(優先度・締切) — は、前回の改訂で必須対応事項へ取り込み済みである。

運用を続けた結果、次の欠落が見えた。抱えるプロジェクトの数や構成は日々変わるのに、
大局視点の画面配置は hide/show と手動リサイズを繰り返して毎回作り直しており、その
手間が全体像の一望を妨げていた。また、作者は作業単位を頭の中で「プロジェクト」と
呼んでいるのに、製品の語彙は「グループ」のままだった。この 2 点 — hide の選択式化・
登録レイアウトの適用・「プロジェクト」への全面改名 — は前回の改訂で必須対応事項へ
取り込み済みである。

続く改訂では、日々触る中で見えた 4 つの摩擦 — リモート split がローカルに戻ること、
hidden なプロジェクトを一望する場所がないこと、ノート編集の取り消し・やり直し、優先度の
毎朝リセット — を必須対応事項へ取り込み、実装済みである。

運用を続けた結果、当初の想定に反して、抱えるプロジェクトの数はさらに増えた。増えたのは
画面に同時に並べる数ではなく、抱えてはいるが今は画面に出していないプロジェクトの方で
ある。これに伴い、大局視点の主役が入れ替わる。これまでの大局視点は「画面に並ぶ端末
そのもの」であり、プロジェクト一覧は hidden の復帰導線に過ぎなかった。今回はこの主従を
逆転させ、**hidden を含む全プロジェクトを載せた一覧を、全体像を把握し統括管理する台帳に
昇格させ、画面配置はその一覧の状態から自動的に導かれる投影とする**。人間が画面配置に
持つ裁量は「同じ表示数に対する好みの割り方」だけになる。

台帳への昇格後、締切の入力だけが日付文字列のタイプを要し、台帳を素早く整える動作として
重いままだった。今回は締切セルの Space 送りを必須対応事項へ取り込む。

利用者は基本的に作者一人である。将来的に他者が使う可能性は否定しないが、
今回の成功は「作者が使えること」で判定する。

## 思想

1. **全体像の把握が最優先。** この製品は「複数プロジェクトを抱える人間が、全体像を
   失わずに前進する」ために存在する。機能の追加可否に迷ったら「それは全体像の把握を
   助けるか」で判断する。

2. **端末領域を恒久的に食う UI は作らない。** 追加 UI は呼び出したときだけ現れ、
   抜ければ端末が全面に戻る。常時表示と迷ったら、常時表示しない側を選ぶ。

3. **上流由来のターミナルコアは極力触らない。** VT 実装・レンダラ・フォントスタック・
   シェル統合は Ghostty から継承した資産であり、fork 固有の機能は macOS アプリ層と
   action 層に閉じる。コアの改変なしに実現できない要求が出た場合は、勝手に踏み込まず
   人間に相談する。

4. **判断ロジックはモデル層に置く。** 「何を表示するか」「何を保存するか」の判断を
   View に持たせない。検証可能性は後付けの品質目標ではなく設計制約である。テストしやすい
   設計とそうでない設計で迷ったら、テストしやすい方を選ぶ。

5. **速度より正しさ。** 期限がないため、動くが根拠のない実装より、遅くても検証された
   実装を選ぶ。

必ず人間に委ねる判断:

- キーバインドの割り当て(既存キーとの衝突が判明した場合の代替キー選定を含む)
- UI の最終的な見た目
- 単一ウィンドウ・タブ無しという構造そのものを変える判断

## 前提事項

- 本プロジェクトは Ghostty(MIT License)の fork であり、macOS 専用・単一ウィンドウ
  である。GTK(Linux/FreeBSD)アプリ、タブ、複数ウィンドウ、quick terminal、
  AppleScript、App Intents、Services 連携は既に削除済みである。
- ビルドには Zig 0.15.x と Xcode を要する。主要コマンドは `zig build`
  (macOS アプリを含むフルビルド)、`just test`(Zig コアのテスト)、
  `just swift-test`(Swift のユニットテスト `XGhosttyTests`)である。
  `just build-app` は `zig build` と等価の薄いラッパーであり、自動検証では
  `zig build` を直接用いる。
- `XGhosttyUITests` は headless 環境でクラッシュするため、自動検証の対象にしない。
- プロジェクトレイヤー(旧 group レイヤー)は `macos/Sources/Features/Projects/` 配下に
  Swift で閉じている(旧 `Groups/` からの改名は完了済み)。ノート・プライマリーペイン・
  優先度・締切・レイアウト適用・プロジェクト一覧・リモート split・優先度の毎朝リセット・
  一覧のセル編集と並べ替え・次トリガー・レイアウト型の記憶と自動適用もここに実装し、
  ノート・優先度・締切・次トリガー・行順・列順・レイアウト型の状態は `ProjectState` に
  持たせる。keybind の追加は既存のプロジェクト action と同じ流儀に従う。
- リモート split の前提として、リモート側のシェルでも Ghostty のシェル統合が動作し、
  OSC 7 でホスト名とカレントパスが報告される。新ペインの再接続は報告されたホスト名への
  `ssh <host>` とし、ユーザー名・鍵・ポートは `~/.ssh/config` 等の ssh 設定に任せる
  (元ペインの ssh コマンドラインは再現しない)。
- fork 固有の機能のために新規の外部依存は追加しない。
- `SPEC.md`(プロジェクトレイヤーの設計書)、`AGENTS.md`、`README.md` は実装
  ドキュメントであり、実装に合わせて更新してよい。仕様書と実装を乖離させないことを
  優先する。
- Linux 対応は将来の可能性として存在するが、プロジェクトレイヤー自体が Swift に閉じて
  いる以上、それはレイヤーごとの再設計を伴う独立した大仕事である。したがって今回の
  実装は移植性を一切考慮せず、Swift に閉じて作る。
- 明確な期限はない。
- 本プロジェクトは GUI アプリケーションであり、画面の見た目は自動検証できない。
  目視確認は人間が実機で行う。
- xcodebuild / zig のツールチェーンは OS sandbox 下で構造的に動作しない
  (XPC サービス接続、ユーザー一時領域への書込み、依存取得のネットワーク)。
  自律セッションは OS sandbox を外して運用する。
- profile: unsandboxed

    - Shift+Space で 1 日戻り、今日からさらに戻すと未設定になる。未設定では何も

    - Space 送りの各押下は編集セッションに属さず、即時に確定値となる
21. プロジェクト一覧の実装が揃った後、人間が実機で一度だけ以下を目視確認し、確認が

    - Space で表示列がその場で切り替わり、背後のレイアウトが即座に組み直される。

    - visible な行で `Cmd+Enter` するとそのプロジェクトに focus して一覧が閉じ、

    - 行が収まらない数のときにスクロールし、カーソルに追従する
    - 一覧の見た目がターミナルに馴染む
    - 締切セルで Space を押すたびに今日 → +1 日と進み、Shift+Space で戻り、今日から

    - リセットによって並び順は変わらない

    - 一望モードの表示内容に次トリガーが含まれる

## 必須対応事項

1. プロジェクトごとに、人間が手書きする短いノートを保持できる。
2. ノートは最大 10 行とし、10 行を超えて保持しない。
3. ノートはプロジェクト名と同様に永続化され、アプリ再起動後に同じプロジェクトへ
   復元される。
4. ノートはプロジェクトに属し、プロジェクト内のペイン(split)には属さない。
5. `Cmd+E` で focused プロジェクトのノート編集オーバーレイが開き、複数行を編集でき、
   `Cmd+Enter` で保存して閉じる。
6. ノート編集オーバーレイで Esc を押すと、編集内容を破棄して閉じ、開く前の本文が
   保持される。破棄に確認は挟まない。
7. `Cmd+Enter` の既定割り当てである fullscreen を解除する。
8. `Cmd+Opt+E` で一望モードをトグルし、visible な全プロジェクトの上にそれぞれのノートが
   同時にオーバーレイ表示される。再度 `Cmd+Opt+E` を押すか Esc を押すと抜ける。
9. 一望モードの表示対象は visible なプロジェクトのみとし、hidden なプロジェクトの
   ノートは表示しない。
10. zoom 中に一望モードへ入った場合は zoom を解除してから全プロジェクトに重ねる。
11. 一望モードは閲覧専用とし、モード中にノート編集も focus 移動も行わない。
12. 一望モードで枠に収まらないノートは切り詰めて表示し、レイアウトを壊さない。
    編集オーバーレイでは全文が見える。
13. ノートに関する UI は端末領域を恒久的に占有しない。呼び出したときだけ表示され、
    抜ければ端末が全面に戻る。
14. 既存のプロジェクト機能(列挙・zoom・序数ジャンプ・hide/show・rename・close)
    および上流由来のターミナル動作を退行させない。ただし以下の意図的変更は例外とする:
    `Cmd+Enter` の fullscreen 既定割り当ての解除(fullscreen は `Ctrl+Cmd+F`・Window
    メニュー・緑ボタンから引き続き到達できる)、全体ビューの描画をプライマリーペインのみ
    に変えること、全体ビューでのペイン系操作の no-op 化、zoom 解除時に focus を
    プライマリーペインへ寄せること、プロジェクトを閉じる操作の確認を常時化すること、
    最後のペインのシェル exit でプロジェクトを閉じず終了済み状態で残すこと、ノート編集
    オーバーレイ中の Cmd+A / C / X / V をエディタのテキスト編集に向けること、`Cmd+S` /
    `Cmd+Shift+S` へのソートアクションの割り当て、「グループ」→「プロジェクト」への
    全面改名(文言・action 名・識別子・ディレクトリ名)、リモートペインの split 先を
    リモート同パスにすること、hidden シェルフの廃止と復帰導線のプロジェクト一覧への
    一本化、`Cmd+L` のプロジェクト一覧とレイアウト選択の `Cmd+Opt+L`、ノート編集
    オーバーレイ中の Cmd+Z / Cmd+Shift+Z をエディタの取り消し・やり直しに向けること、
    優先度の毎朝リセット、`Cmd+N` / `Cmd+Opt+N` のノート操作を `Cmd+E` / `Cmd+Opt+E` へ
    移すこと、`Cmd+E` の `search_selection` 既定割り当ての解除(機能自体は残す)、
    `Cmd+Opt+H` を hide 選択画面から focused プロジェクトの即時 hide へ戻すこと、
    `Cmd+Opt+D` / `Cmd+Opt+Shift+D`(`new_project_split`)の廃止と新規作成の
    プロジェクト一覧への一本化、登録レイアウト 11 種のレイアウト型(形 × 向き)への
    置き換えと表示数変化時の自動適用、プロジェクト単位のレイアウト resize/equalize の
    廃止(zoom 中のペイン resize は存続)、一覧の Enter を下セル移動に変え focus を
    `Cmd+Enter` に移すこと、優先度・締切の設定入口をノート編集オーバーレイから一覧へ
    移すこと。
15. ノートの保持・復元・表示対象の判断ロジックはモデル層に置き、`XGhosttyTests` から
    検証可能にする。
16. `SPEC.md` と `README.md` を、実装したノート層の仕様に合わせて更新する。
    `README.md` の Building 節には `zig build` / `just test` / `just swift-test` の
    3 つの検証コマンドをすべて載せる。
17. 各ペインはプライマリーフラグを持つ。プロジェクト内の最初のペインはプライマリーとし、
    それ以降に作られたペインは非プライマリーとする。
18. プライマリーペインはプロジェクト内で常に 1 つのみとする。
19. 全体ビュー(非 zoom)では、各プロジェクトはプライマリーペインのみを描画する。
    プロジェクトに zoom した局所視点では従来どおり全ペインをレイアウトのまま表示する。
20. 全体ビューでのキーボード入力・focus はプライマリーペインへ向く。zoom 解除時に
    focus がプライマリー以外のペインにあった場合はプライマリーへ寄せる。
21. 全体ビューではペイン系操作(分割・ペイン間 focus 移動・ペイン zoom・ペインの
    resize/equalize)を no-op とする。ペイン操作は zoom 中のみ有効とする。
22. zoom 中に focused ペインをプライマリーへ指定する action を追加し、`Cmd+P` に
    割り当てる(素の `Cmd+P` に既存割り当てが無いことは確認済み)。指定時、元の
    プライマリーは解除される。
23. プライマリーペインが閉じた場合(シェルの exit・`Cmd+W`・process 死のいずれでも)、
    プロジェクトに他のペインがあれば分割木上の最近傍 leaf を昇格する。プライマリーが
    最後のペインの場合は 28〜31 項に従う(シェル exit では終了済み状態で残り、
    close 操作では確認を経て閉じる)。
24. プライマリーフラグはペインレイアウトと同じ経路で永続化され、アプリ再起動後に
    同じペインへ復元される。不正な保存(プライマリー 0 個/複数)は復元時に 1 つへ
    正規化する。
25. プライマリーの印は、zoom 中かつプロジェクト内に複数ペインがあるときだけ、
    プライマリーペインの右上に表示する。全体ビューおよび単一ペインのプロジェクトでは
    表示しない。
26. プライマリーの判断ロジック(既定付与・唯一性・昇格・復元時正規化・全体ビューの
    表示対象)はモデル層に置き、`XGhosttyTests` から検証可能にする。
27. `SPEC.md` と `README.md` を、実装したプライマリーペイン層の仕様に合わせて更新する。
28. プロジェクトを閉じる操作(`close_project`、および最後のペインでの `Cmd+W`)では、
    実行中プロセスの有無によらず常に確認ダイアログを表示する。ダイアログは既存の
    実行中プロセス確認と同じ形式(Cancel / Close)を流用する。
29. 最後のペインのシェルが exit したとき(正常終了・異常終了・process 死のいずれでも)、
    プロジェクトを閉じず、ペインを「終了済み」状態のまま残す。ノートを含むプロジェクト
    の情報は保持される。
30. 終了済み状態のペインで Enter を押すと、新しいシェルが起動して同じペインで作業を
    再開できる。
31. プロジェクトとその情報(ノート等)が失われる経路は、確認ダイアログを経た明示的な
    close 操作のみとする。アプリ終了・再起動では従来どおり全プロジェクトが復元される。
32. ノート編集オーバーレイ表示中は、標準的なテキスト編集ショートカット(Cmd+A 全選択・
    Cmd+C コピー・Cmd+X 切り取り・Cmd+V 貼り付け・Cmd+Z 取り消し・Cmd+Shift+Z
    やり直し)がエディタに対して効く。取り消し履歴はそのオーバーレイを開いてから
    閉じるまでの編集セッション内に限り、対象はノート本文のみとする。
33. 貼り付けにより 10 行を超えた場合も、従来の手入力と同様、保存時に先頭 10 行へ
    切り詰める(2 項の挙動を変えない)。
34. プロジェクトごとに優先度(high / medium / low / 未設定)を設定できる。既定は
    未設定。
35. プロジェクトごとに締切(日付のみ、時刻なし)を設定できる。既定は未設定。不正な
    日付入力は保存時に弾き、未設定として扱う。
36. 優先度・締切はプロジェクト一覧のセルで設定・変更でき(ノート編集オーバーレイからは
    設定しない)、ノートと同様に永続化され、アプリ再起動後に同じプロジェクトへ復元
    される。
37. プロジェクトのラベル帯に、優先度の控えめな印と締切を表示する。未設定の項目は
    表示しない。
38. 一望モードでは、ノートと併せて優先度・締切・次トリガーを表示する。
39. 締切を過ぎたプロジェクトは、ラベル帯・一望モードで控えめに強調する。強調は
    「超過」の 1 段階のみとし、「間近」等の段階分けはしない。
40. hidden を含む全プロジェクトの行を優先度順(high → medium → low → 未設定。同順位内は
    現在の相対順を維持)に並び替えるアクションを `Cmd+S` に割り当てる。
41. hidden を含む全プロジェクトの行を締切順(近い順。未設定は末尾、同日内は現在の
    相対順を維持)に並び替えるアクションを `Cmd+Shift+S` に割り当てる。
42. ソートは明示的なアクション実行時のみ行い、優先度・締切の変更によって自動では
    並び替えない。ソート後の並びは次のソートまたは手動の並べ替えまで維持され、序数
    ジャンプ(Cmd+1〜9)はソート後の並びに追従する。ソートは一覧を開いていなくても効く。
43. ソートの対象は hidden を含む全行とし、visible な行を上から数えた順が序数になる。
    次トリガー順のソートは設けない。
44. 優先度・締切・次トリガーの保持・復元・ソート順・締切超過判定・終了済み状態の判断
    ロジックはモデル層に置き、`XGhosttyTests` から検証可能にする。
45. `SPEC.md` と `README.md` を、実装した削除保護・ショートカット対応・優先度・締切層の
    仕様に合わせて更新する。
46. `Cmd+Opt+H` は focused プロジェクトを即座に hidden にする(選択画面は開かない)。
47. `Cmd+Opt+H`・一覧の表示トグルのいずれでも、visible な全プロジェクトを隠すことは
    できず、最低 1 つは visible に残る。
48. 隠したプロジェクトの復帰導線はプロジェクト一覧のみとし、hidden シェルフは廃止済みの
    ままとする。
49. レイアウト型は形(横長型・縦長型・台座型)と向き(行送り・列送り)の組み合わせと
    する。横長型は行数を √n に最も近い整数とするグリッドに、プロジェクトを上の行から
    できるだけ均等に配り、行の高さと行内の幅を等分する。縦長型はその転置とする。
    台座型は n−1 個を上部に配置し、1 個を最下段に全幅横長で置く。横長型・縦長型では
    向きは序数の進み方だけを変え、形は変えない。台座型では、行送りは上部を横長型の
    規則で、列送りは縦長型の規則で配置する。
50. 各 visible 数(1〜9)に対して、形 3 種 × 向き 2 種のうち配置も序数の進み方も
    完全に一致するものは 1 つに畳み、残りを選択肢とする。選択肢が 1 つのとき
    `Cmd+Opt+L` は選ぶものが無い旨を示すだけとする。
51. `Cmd+Opt+L` でレイアウト型の選択オーバーレイが開き、現在の visible 数に対する
    選択肢を矢印キーで選んで Enter で適用し、Esc で何も変えずに閉じる。プロジェクト数は
    一切変えない。オーバーレイは呼び出したときだけ表示され、抜ければ端末が全面に戻る
    (zoom 中に呼び出した場合の挙動は定めず、実装に任せる)。
52. 選んだレイアウト型は永続化され、アプリ再起動後も維持される。既定は横長型・行送りと
    する。
53. レイアウト適用時、visible なプロジェクトは一覧の行順のまま、選んだ型の向きに従って
    スロットへ割り当てる(行送りは上の行から左→右、列送りは左の列から上→下、台座型の
    最下段は最後)。序数(Cmd+1〜9)は適用後の配置に追従する。
54. visible なプロジェクトの数が変わったとき(一覧の表示トグル・`Cmd+Opt+H`・新規
    作成・close のいずれでも)、記憶しているレイアウト型で新しい数に対する配置を
    自動適用する。一覧を開いたまま切り替えた場合も背後で即座に組み直す。visible 数が
    変わらない操作(終了済み状態への遷移等)では発火しない。
55. プロジェクト単位のレイアウト resize / equalize を廃止する。zoom 中のプロジェクト内
    ペイン(split)の resize / equalize は従来どおり有効とする。
56. レイアウト型のスロット計算・完全一致の畳み込み・向きの割り当て順・自動適用の判断
    ロジックはモデル層に置き、`XGhosttyTests` から検証可能にする。
57. 「グループ」を「プロジェクト」へ全面改名する:ユーザー可視文言(メニュー・
    ダイアログ等)、fork 固有の action 名(`hide_group` → `hide_project` 等)、コード
    内部識別子(`GroupState` → `ProjectState` 等)、ディレクトリ・ファイル名
    (`macos/Sources/Features/Groups/` → `Projects/` 等)、および SPEC.md / README.md の
    用語。上流由来のターミナルコアの語彙・識別子には触れない。
58. 改名は挙動を変えない純粋なリネームとし、既存機能を退行させない。キーバインド設定
    等の後方互換は従来どおり保証しない。
59. `SPEC.md` と `README.md` を、実装したレイアウト型・自動適用・hide の仕様と改名後の
    語彙に合わせて更新する。
60. リモートホストにいるペイン(シェル統合が OSC 7 で報告するホストがローカルでない)
    を split したとき、新ペインは同じホストへ ssh で接続し、同じパスで開く。対象は
    split のみとし、新規プロジェクト作成で作られる新プロジェクトはローカルで開く。
61. リモートにいると判定できない場合、または接続に失敗した場合は、従来どおりローカルで
    開く。
62. リモート判定(リモートか否か・ホスト・パスの抽出・起動コマンドの決定)はモデル層に
    置き、`XGhosttyTests` から検証可能にする。上流のターミナルコアの改変なしに実現
    できないと判明した場合は、着手せず人間に相談する。
63. `Cmd+L` でプロジェクト一覧オーバーレイが開き、hidden を含む全プロジェクトを表形式で
    列挙する。列は既定順で「表示・タイトル・優先度・締切・次トリガー・ノート」とし、
    ノート列は 1 行目を表示する。未設定の項目は空欄とする。オーバーレイはウィンドウの
    幅・高さそれぞれ 8 割程度を占め、呼び出したときだけ表示され、閉じれば端末が全面に
    戻る。行が収まらないときはスクロールし、セルカーソルに追従する(zoom 中に呼び出した
    場合の挙動は定めず、実装に任せる)。
64. 一覧の行の並びは visible / hidden で区画分けせず単一の並びとし、序数(Cmd+1〜9)は
    visible な行を上から数えた順とする。行順・列順は永続化される。
65. 一覧はセルカーソルを持ち、`Tab` 右 / `Shift+Tab` 左 / `Enter` 下 / `Shift+Enter` 上
    (矢印キーも同じ)で移動する。行末の `Tab` は次の行の先頭へ折り返し、最終行の
    `Enter` はそこで止まる。テキスト列(タイトル・締切・ノート)は文字を打つと編集が
    始まり、`Enter` / `Tab` で確定して移動、`Esc` でその編集だけを取り消す。選択式の列
    (表示・優先度・次トリガー)は `Space` で値が循環する(表示は 2 値のトグルで、
    hide/show は即時反映)。編集していないときの `Esc` は一覧を閉じる。
66. 一覧のノート列の編集はノートの 1 行目だけを書き換え、2 行目以降は保持する。
    `Cmd+Opt+E` は一覧の中では全行のノートを全行表示するトグルとし(閲覧のみ・行ごと
    ではなく一括・状態は永続化しない)、複数行の編集は `Cmd+E` のオーバーレイで行う。
67. 一覧で `Cmd+↑` / `Cmd+↓` はカーソル行を上下に 1 つ動かし、`Cmd+←` / `Cmd+→` は
    カーソル列を左右に 1 つ動かす。
68. `Cmd+N` は新規プロジェクト作成とする。一覧の中で押すとカーソル行の直下に新規
    プロジェクトが挿入され、通常の新規作成と同様に新しいシェルが起動し、カーソルは
    新しい行のタイトル列に移りその場でタイトルを入力できる。一覧の外で押すと一覧が
    開いて同じ状態になる。新規行は visible 数が 9 未満なら visible、9 なら hidden と
    する。`Cmd+Opt+D` / `Cmd+Opt+Shift+D`(`new_project_split`)は廃止し、新規
    プロジェクトの作成導線は一覧のみとする。
69. 一覧で `Cmd+Enter` を押すとカーソル行のプロジェクトへ focus して一覧を閉じる。
    hidden な行では無効(何も起きない)。
70. 一覧の行の内容・並び・セル編集の確定と取り消し・締切の Space 送りの日付計算・
    トグル可否・focus 可否・新規行の表示状態の判断ロジックはモデル層に置き、
    `XGhosttyTests` から検証可能にする。
71. プロジェクトごとに次トリガー(自分 / チームメンバー / 組織外部人 / イベント /
    未設定)を設定できる。既定は未設定。一覧のセルで設定・変更し、優先度と同様に
    永続化され、アプリ再起動後に復元される。プロジェクトのラベル帯には表示しない。
72. 毎日ローカル時刻 6:00 を境界として、全プロジェクト(hidden を含む)の優先度を
    未設定に戻す。締切・ノート・次トリガーは変更しない。
73. リセットは「最後にリセットした日付」を永続化し、それが現在の作業日と異なるときに
    1 回だけ実行する。実行タイミングは、アプリ起動時、および稼働中に境界を跨いだとき
    (スリープ復帰・再アクティブ化を含む)とする。通知や印は出さない。
74. 自動リセットによって並び替えは行わない(ソートは従来どおり明示アクション時のみ)。
75. リセットの判定ロジック(境界・対象・1 日 1 回)はモデル層に置き、`XGhosttyTests`
    から検証可能にする。
76. `SPEC.md` と `README.md` を、実装したリモート split・プロジェクト一覧のセル編集と
    並べ替え・締切の Space 送り・次トリガー・Undo/Redo・優先度リセット・キー変更の
    仕様に合わせて更新する。
77. 締切セルでは、文字入力に加えて Space 送りで日付を設定できる。編集していない状態で
    `Space` を押すと、未設定なら今日が設定され、日付があればその日付から 1 日進む。
    `Shift+Space` は 1 日戻し、今日の状態からさらに戻すと未設定に戻る。未設定の状態
    での `Shift+Space` は何もしない。各押下は選択式の列と同様に即時反映され、`Esc`
    でも取り消されない。文字入力(タイプによる編集と確定・取り消し)は従来どおり残し、
    過去日の設定は文字入力で行う。

## 任意対応事項

- ヘッダー帯のクリック等、マウスからノートを開く導線(今回はキーバインドのみで足りる。
  余力があれば)。
- ノート編集オーバーレイ・一望モード・プライマリー印の見た目の洗練(配色・余白・
  アニメーション)。
- 全体ビューで、プロジェクトに非プライマリーペインがあるとき、その存在が分かる控えめな
  インジケータ(例:ペイン数バッジ)の表示。

## 非対応事項

恒久的にやらないこと:

- タブ、複数ウィンドウ、quick terminal、AppleScript、App Intents、Services 連携の復活。
- 上流 Ghostty への追従、および上流へのコントリビュート。
- 他者向けの整備:署名済み配布物(.app / Homebrew)、ユーザー向けドキュメント、
  設定の後方互換保証。
- ノートの外部同期(クラウド保存、ファイル書き出し、他デバイス共有)。
- ユーザー定義レイアウトの登録機能(レイアウト型は組み込みの形 3 種 × 向き 2 種で
  完結する)。
- visible なプロジェクト数の 9 超え、およびそれに伴う序数ジャンプ(Cmd+1〜9)の拡張。
  登録総数に上限は設けないが、同時に画面へ並ぶ数は 9 までとする。
- `SPEC.md` の「2. 非目的」に列挙済みの各項目:tmux / zellij 互換、floating pane、
  live session 完全復元、scrollback / PTY 状態の永続復元、drag & drop による
  プロジェクト移動、プロジェクト入れ替え UI。

現段階では実施しないこと(将来の昇格候補):

- 端末が観測した各プロジェクトのライブ状態表示(入力待ち・実行中・正常終了・異常終了)
  (現段階では実施しない。エージェントが入力待ちで止まっているのを見落とし、
  プロジェクトを長時間放置してしまう事象が実際に起きたら、update-essence で
  必須対応事項/任意対応事項への昇格を検討)。
- Linux / GTK 対応(現段階では実施しない。作者の常用開発マシンが macOS でなくなったら、
  update-essence で必須対応事項/任意対応事項への昇格を検討)。

## 用語

- **プロジェクト** — ユーザーから見た作業文脈の単位。旧称「グループ」であり、製品の
  語彙は「プロジェクト」に統一済み。内部実装では `ProjectState` / `ProjectRef` が
  対応する。
- **大局視点** — zoom を解除し、visible な全プロジェクトが同時に画面に並んでいる状態。
- **局所視点** — 特定のプロジェクトに zoom し、その端末作業に没入している状態。
- **ノート** — プロジェクトに紐づく、人間が手書きする短いメモ。最大 10 行。
  プロジェクト名と同様に永続化される。
- **一望モード** — `Cmd+Opt+E` で入る閲覧専用モード。visible な全プロジェクトの上に
  それぞれのノート・優先度・締切・次トリガーが同時にオーバーレイ表示される。zoom 中に
  入ると zoom は解除される。
- **全体ビュー** — 大局視点と同義。zoom していない状態で、visible な全プロジェクトが
  同時に画面に並んでいる画面。
- **プライマリーペイン** — プロジェクト内で常に 1 つだけ存在する代表ペイン。既定では
  最初に作られたペインがプライマリーとなる。全体ビューではこのペインだけが描画される。
  zoom 中に `Cmd+P` で focused ペインへ付け替えられる。
- **優先度** — プロジェクトに設定する high / medium / low / 未設定 の 4 値。既定は
  未設定。「今日のフォーカス」を表し、毎朝ローカル 6:00 を境界に未設定へ戻る。
- **締切** — プロジェクトに設定する日付(時刻なし)。未設定を許す。
- **次トリガー** — プロジェクトを次に動かす主体。自分 / チームメンバー / 組織外部人 /
  イベント / 未設定の 5 値。既定は未設定。人間が書き込む情報であり、端末が観測する
  ライブ状態とは別物。
- **ソート** — `Cmd+S`(優先度順)/ `Cmd+Shift+S`(締切順)で実行する明示的な
  並び替えアクション。hidden を含む全行の並びを並び替え、序数はその結果の visible な行を
  上から数えた順になる。
- **終了済み状態** — 最後のペインのシェルが exit した後、プロジェクトが閉じずに
  残っている状態。ノート等の情報は保持され、Enter で新しいシェルを起動して再開できる。
- **プロジェクト一覧** — `Cmd+L` で開く表形式のオーバーレイ。hidden を含む全プロジェクト
  を表示・タイトル・優先度・締切・次トリガー・ノートの列で列挙する台帳。セル単位で
  編集でき、行順・列順を手動で入れ替えられ、新規プロジェクトの作成と hidden な
  プロジェクトの復帰の唯一の導線。行順は序数(Cmd+1〜9)の元になる。
- **レイアウト型** — 表示数 n に対する画面配置の選択肢。形(横長型・縦長型・台座型)と
  向き(行送り・列送り)の組み合わせで定まり、完全一致するものは 1 つに畳む。
  `Cmd+Opt+L` で選び、選んだ型は記憶され、表示数が変わるたびに同じ型で自動適用される。
- **横長型** — 行数を √n に最も近い整数とするグリッドに、上の行からできるだけ均等に
  配り、行高・行内幅を等分する形。
- **縦長型** — 横長型の転置。列数を √n に最も近い整数とし、左の列からできるだけ均等に
  配り、列幅・列内高を等分する形。
- **台座型** — n−1 個を上部に配置し、1 個を最下段に全幅で置く形。上部は、行送りでは
  横長型の規則、列送りでは縦長型の規則で配置する。
- **行送り / 列送り** — 序数(Cmd+1〜9)の進む向き。行送りは上の行から左→右、列送りは
  左の列から上→下。横長型・縦長型では向きは序数の進み方だけを変え、形は変えない。
- **リモートペイン** — シェル統合が OSC 7 で報告するホストがローカルでないペイン。
- **作業日** — ローカル時刻 6:00 から翌 6:00 までの区間。優先度リセットの単位。
